# 待验证：含 slot 组件「模板结构恒定」

## 结论先写

项目里有一条约定：**含 slot 的组件模板结构保持恒定**（不靠 `v-if` 增删兄弟节点切换形态，需要"收起"时用高度 0 或空文案占位）。

约定**继续执行**——它成本很低（多留一两个空节点），出错代价是整个区块错位。但它的依据目前只有一次事故记录，**不是可复现的平台行为**。本文记录已测范围与复验方法，避免后续把它当成已证实的平台约束引用。

## 原始说法

`77edcde`（2026-11-01，主分支恢复到事故前快照）带入的 `PageTopbar` 注释：

> 实测坑：本平台渲染器对「v-if 换过结构之后再补插节点」会插错位 —— 歌曲列表页第二次进多选时，右上角 slot（全选）被插到 `.ptb-fill` 前面、整体左移 ~180px。根因是旧写法用 `v-if="link"` / `v-if="!link"` 两套节点切换，第二次切换后 slot 落错位。

即：**S7 上、`list` 页、第二次进入多选**时观察到的 UI 错位。

## 已测（X3S，800×254，2026-11-27）

探针页 `pages/probe_slot/probe_slot_q.vue`，每 2.5 秒切换一个阶段，逐帧截图后按像素扫描判读。四组场景：

| 组 | 场景 | 结果 |
|---|---|---|
| Q1 | 父级 `v-if` + 组件内部节点 `v-if` + slot 内容，三者同帧变化 | 正常，slot 始终在末尾 |
| Q2 | slot 内容在 `v-for` 里，数量 0→1→2→3 循环 | 正常，数量与位置都对 |
| Q3 | 具名 slot（`v-slot`，slot 落在包裹容器内） | 正常 |
| Q4 | 嵌套：父 slot 里再放一个含 slot 的子组件 | 正常 |

关键一帧（阶段 `E=0 S=1`，内部结构刚变完、slot 内容刚插入）：

```
Q1: 蓝[5,25) 绿[25,215) 品红[215,245)      ← slot 在末尾，未跑到 fill 前面
Q3: 蓝[5,25) 绿[25,215) 青[215,245)
Q4: 蓝[5,25) 白[25,45) 青[45,235) 黄[235,245)
```

10 个阶段循环、16 帧，无一次错位；设备日志无相关 error。

## 未测（这才是关键）

1. **S7**——事故机型，本轮一次都没连上（adb 与 ssh 两条通道均不通）。X3S 是 RK3566 / 800×254，S7 是 1020×240，渲染路径不同。
2. **原始场景的三要素未同时复现**：
   - 同页**重复挂载**（`list.vue` 会挂两遍，本仓库已知）；
   - **第二次**进多选（同一实例上第二次换结构，而非首次）；
   - slot 内容**异步到达**（`selectingAll` 拉全量后才显示）。

本轮探针是"新挂载 + 结构切换"，可能正好绕开了触发条件。

## 复验方法

探针在被忽略的工作树 `.agents/worktrees/test/verify-fw-claims` 里（未合入）。组件形态：

```vue
<!-- 组件：中间 fill 撑满，slot 在末尾；extra 控制内部节点 v-if -->
<view class="pss">
  <view class="pss-t"></view>
  <view class="pss-fill"></view>
  <view class="pss-extra" v-if="extra"></view>
  <slot></slot>
</view>
```

判据：截图后扫该行像素，`fill` 色段应一直延伸到 slot 色段之前；若 slot 色段出现在 `fill` 之前即为错位。

步骤（入口页临时指向探针）：

```bash

# 2. 构建 + 装机（独立 appid，不碰正式数据）

python ../../tools/dictpen-dev/devctl.py --project . --device <s7|x3s> install --no-build
# 3. 逐帧截图（每次间隔 ~0.8s，覆盖 10 个阶段）
python ../../tools/dictpen-dev/devctl.py --project . --device <s7|x3s> capture shot.png
```
