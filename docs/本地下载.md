# 本地下载与歌单本地索引

本地下载已从「一个歌曲总列表」重做为「总览 + 分类列表 + 歌单索引」。核心原则：

- **用户下载的文件默认永久保留**；自动流程（移出索引 / 同步）只解除归属，不删文件。
- 「单曲下载」「歌单内歌曲」「遗留歌曲」是**派生视图**，不是目录；文件始终在 `$dataDir/music/`。
- 页面只读文件系统与索引，不维护「索引说有、文件却没有」的第二真相。

## 一、页面结构

### 1. 本地下载（总览）

`downloads`：与主页同款的横向卡片流（卡宽同为 23%），顺序固定为 **歌单 / 歌手 / 专辑**。

- 歌单卡副行：`N 个歌单`（本地索引数量）；歌手卡：`N 位歌手`；专辑卡：`N 张专辑`。
- 顶栏副题：`N 首 · X MB · 可用 Y`；下载中优先显示下载进度。
- 左栏：返回 + 下载队列。多选/删除不在总览页，进入具体列表后操作。

### 2. 本地下载-歌单（索引页）

`dlplaylists`：已添加到本地索引的歌单，外加三个特殊入口。

```
[全部下载]               所有已下载文件
...已添加到本地索引的歌单...
--- 其他 ---
[单曲下载]               用户自己的单曲 / 升级前的遗留文件
[遗留歌曲]               歌单批量下载、但已不被任何索引歌单引用的文件（>0 时显示）
```

- 歌单行副行：`已下载 N / 共 M 首`，与本地文件有差异时追加 `新增 A · 移除 D`。
- 歌单行点击 → `dltracks kind=playlist`；全部/单曲/遗留 → `dltracks` 对应 kind。
- 没有已索引歌单时，在「其他」分组上方显示 info 图标 + 提示文字，文字下方带一根分割线：`暂无本地索引的歌单，在歌单详情页中添加`。
- 没有遗留歌曲时隐藏「遗留歌曲」行，避免空分类挡住底部提示。

### 3. 本地下载-曲目列表

`dltracks` 用 `kind` 复用四种视图：

| kind | 数据 | 状态卡片 | 多选 |
|---|---|---|---|
| `all` | 全部已下载文件（新→旧） | 无 | 删除 |
| `single` | 单曲下载（无引用且非歌单归属） | 无 | 删除 |
| `orphan` | 遗留歌曲（无引用且歌单归属） | 无 | 保留为单曲 / 删除 |
| `playlist` | 某个索引歌单的本地已下载曲目 + 远端 A/D 条目 | 有 | 删除 |

- 点行播放：歌单内 A（远端有、本地未下载）在线时流播，离线提示「离线，这首还没下载」；
  D 与正常行播本地文件。离线起播时队列自动排除未下载的 A 条目。
- **列表顺序：A（远端有、本地没有）→ D（本地有、远端已移除）→ 未变化曲目**。
  这样差异项一定在第一屏，不会因为 50 行/批的分页被埋到几百行之后。
- 差异的视觉：A 行灰字 + 绿色 A；D 行仅歌名白色 + 删除线（别名 / 歌手 / 时长等其余列保持原样式）+ 红色 D，表示文件仍在但已不在远端歌单。
- A/D 标记在列表最右侧的**独立固定列**：歌单内视图即使某行没有标记也保留该列宽度，
  标记出现/消失不会让左侧各列左移或右移。
- 分页每批 50 首；从其它页返回、或拉取/同步后重读时保留已展开的条数，不退回首批。
  歌单索引 / 歌手 / 专辑页同样在 onShow 重读时保留已展开的分页（排序、列数切换才重置）。
- `kind=playlist` 时顶栏标题区可点 → `plinfo` 歌单详情（同在线曲目列表页）；多选态不可点。
  这条入口给 `plinfo` 传 `entry:'dl'`：详情页左栏换成本地语境（底键 = 移除本地索引，
  「删除」下沉到「更多」面板并分成本地删除 / 删除，见 2.1 末尾）。
- 长按行 → `songinfo`。
- 多选：`全选/全不选` 在顶栏右侧；删除是两次点按确认（`armMixin`）。
- 删除文件会同时清 `dlorigin` 归属；若当前队列来自本页（`queueSrc='downloads'`），
  同步移出队列（与旧本地下载页一致）。
- 遗留页多选态额外给「保留为单曲」：把 `playlistOwned` 改成 `userOwned`，文件不动，
  重新分类后从遗留页消失、进入「单曲下载」。

### 4. 歌单内的状态卡片（拉取 / 同步）

仅 `kind=playlist` 显示，作为列表第一项随列表一起滚动（不固定在顶栏下方）：

- 左：`上次拉取：YYYY/MM/DD`（从未拉取显示 `—`）。
- 右：两个带图标按钮「拉取」（`move-down-left`）、「同步」（`refresh-cw`）；按钮圆角与卡片一致（`@radius`）。
- 卡片上下各留 4vh；随列表滚出屏幕后不再占列表高度。
- 忙碌时顶栏副题显示「拉取中... / 同步中...」，下载阶段显示下载引擎的进度文案。

### 5. 本地下载-歌手

`dlartists`：`localmeta.localArtistList()` 聚合本地索引中的所有歌手。

- 行高 32vh（比歌曲行 23vh 高），单行：圆形头像 + 名称 + `N 首` + chevron。
- 头像来源统一为「真头像优先，代表专辑封面兜底」：
  - 真头像缓存键 `arp<歌手id>@60`，URL 来自 `/api/artist/head/info/get` 并落盘到
    `store/artist_meta.json`；在线时列表行按需取，下载完成时也会异步预热（见第四节第 6 条）。
  - 兜底图是**发行时间最新的、有封面的本地专辑**，缓存键 `al<专辑id>@60`——
    下载完成时已预热，离线可命中；歌手详情本地视图用同一张（`@200`）。
  - 两者都没有时显示人形图标。
- 左栏排序键展开面板：**标题（默认 A→Z）/ 数量（默认多→少）**；同键再点切升降序。
- 点行 → `artist` 页并带 `local=1`，强制本地索引视图（只显示已下载曲目/专辑）。

### 6. 本地下载-专辑

`dlalbums`：`localmeta.localAlbumList()` 聚合本地索引中的所有专辑，卡片网格。

- 卡面：专辑封面（取自专辑内歌曲的封面）+ 专辑名(L1) + 专辑艺术家(L2) + `N 首 · 年份`(L3)。
- 左栏排序键展开面板：**排序依据（标题/年份/数量）+ 列数（2/3/4）**。
  默认年份新→旧；标题默认 A→Z；数量默认多→少；同键再点切升降序。
- 默认列数按 `$falcon.env.screenWidth` 选（S7 1020 → 4 列；≥780 → 3 列；其余 → 2 列），
  用户仍可在面板里改。
- 点卡片 → `album` 页并带 `local=1`，强制本地索引视图。

## 二、歌单本地索引

### 1. 数据模型

文件 `$dataDir/store/local_playlists.json`（大表落文件的原因见 [存储层.md](存储层.md)）：

```js
{
  "<playlistId>": {
    id, name, cover, creator, trackCount, updateTime,
    baseIds:   [曲目 id],   // 曾见过的远端曲目集合（含旧快照；D 判定用）
    remoteIds: [曲目 id],   // 最近一次拉取的远端快照
    lastPullAt, addedAt, lastSyncAt,
    meta: { "<id>": { n, a, al, c, d, fee } } // 仅 A 条目的显示/下载元数据
  }
}
```

- 添加索引只抓 `playlist/detail`（`n:0`，`trackIds` 全量）+ 歌单元信息，
  **不下载文件**；`baseIds = remoteIds = 当前远端快照`。
- **A/D 相对本地文件实时计算，不相对 `baseIds` 的“上次快照”**：
  A 是「远端有、本地没有」，D 是「本地有、远端已移除」。因此加入索引前歌单里
  就已有、但一直没下载的曲目，打开本地歌单列表立刻就是 A，不需要等远端再次变动。
- 普通入口（在线曲目列表页点顶栏）：「更多」里的「添加到本地索引」添加；已索引时同一项变「移出本地索引」。
- 从本地下载进入的详情页（`entry:'dl'`）：索引切换是左栏底键；「更多」面板底部另有
  **本地删除** 与 **删除** 两项（都是两次点按确认）：
  - **本地删除**：移除本地索引，并把「移出后会进遗留歌曲」的文件直接删掉（不留孤儿）。
    删除范围 = 本歌单 `baseIds ∪ remoteIds` ∩ 本地已下载 ∩ 不被其它索引歌单引用 ∩
    `playlist` 归属；仍被其它索引歌单引用的文件、用户单曲/无标记文件保留。
  - **删除**：本地删除 + 调 `/api/playlist/remove` 把远端歌单也删掉（仅自己创建的歌单，不可逆）。
- 移出索引只删记录，不删文件。失去所有索引引用的歌单批量下载文件会自动归入「遗留歌曲」。

### 2. 拉取（git fetch）

`pullList(pid)`：

1. 请求最新 `playlist/detail`，更新歌单元信息 + `remoteIds` + `lastPullAt`。
2. 计算 `A = remoteIds − 本地已下载`、`D = baseIds − remoteIds`（且本地有文件）。
3. 为 A 条目补元数据（`/api/v3/song/detail`，300/批），写入 `meta`；不下载音频。
4. 把上一版 `remoteIds` 并入 `baseIds`（保证“曾进过歌单、本地有文件”的曲目在远端移除后
   仍能判成 D），**不碰文件**。A 不依赖 `baseIds`，多次拉取不会丢标记。

离线时直接返回失败，不发起 N 次超时。`pullAll` 会先扫一次本地目录，把 `localIds` 复用到
所有歌单，避免 N 次 exec。

### 3. 同步（git pull）

`syncList(pid)`：

1. 先拉取（同上）。
2. 下载**所有 A 条目**（远端有、本地没有；`downloadSongs(..., {origin:'playlist'})`）。
3. 把 D 从 `baseIds` 移除；**不删文件**（策略 A）。
4. 成功后 `baseIds = remoteIds`（当前远端快照）；失败/取消的 A 保持 A，下次重试。
5. `meta` 只保留仍为 A 的条目。

`baseIds` 以 `remoteIds` 顺序重建，保证歌单内顺序与远端一致。

### 4. 下载全部

歌单详情「更多」→「下载全部」：

- **已索引**：先拉取，再抓整张远端曲目并下载；完成后 `baseIds = remoteIds`，
  D 随之移除（文件保留）。等价于「同步 + 补齐所有未下载项」。
- **未索引**：按用户单曲下载（`origin=manual`），不创建索引，也不产生「没有索引却有遗留」的状态。
- 大歌单（>1000 首）通过 `trackIds` + `/api/v3/song/detail` 分批取，不依赖 detail 内联曲目。

### 5. 自动拉取

- 设置入口：设置 → 音质与存储 → **自动拉取**（`config.autoPull`，默认 **关**）。
- 启动链 `boot.js` 在登录态就绪后异步调用 `pullAll()`：逐个拉取已索引歌单，
  只更新远端快照，不下载/不删文件；不 await，不拖慢首页。
- 离线 / 未登录时直接跳过；失败只记日志，下次启动再试。

## 三、下载归属与三类派生

### 1. 两个归属标记

storage 单 key `bpncm_dl_origin`：`{ "<songId>": 1|2 }`（这张表只有几百字节，仍留在 storage）。

| 标记 | 写入时机 | 含义 |
|---|---|---|
| `1 = user` | 播放器下载键、专辑/歌手/搜索页、列表多选下载；升级前的已有文件默认按 user 处理 | 用户自己的单曲 |
| `2 = playlist` | 只在「下载全部」、同步、自动同步（且该歌单已索引）时写 | 为本地索引歌单批量下载 |

规则：

- `user` 是终态，歌单批量下载不会覆盖；`playlist` 写入前看已有标记。
- 歌单批量下载**跳过已存在文件**时：没有标记 → 补 `user`（遗留文件按用户资产处理）；
  已有标记 → 保持。绝不把用户已有文件认领成歌单归属。
- 删除文件（任何入口）→ 清标记；清空已下载 → 清全表。

### 2. 三类派生

设 `referenced(id)` = 存在任一已索引歌单，其 `baseIds ∪ remoteIds` 包含该曲目：

| 条件 | 分类 |
|---|---|
| `referenced(id)` | 歌单内（对应歌单的曲目列表；可同时属于多个歌单） |
| `!referenced && playlistOwned && !userOwned` | **遗留歌曲** |
| `!referenced && (userOwned || 无标记)` | **单曲下载** |

关键性质：

- 移出索引 / 同步 D **不需要维护孤儿表**；分类由当前索引状态 + 归属标记动态派生。
  崩溃、重复同步、重启都不会留下陈旧状态。
- 重新加回索引、或被另一个索引歌单引用，遗留自动回到歌单视图。
- 遗留文件手动下载一次（播放器下载键，或遗留页「保留为单曲」）→ 转为 `userOwned`，
  从遗留页消失、进入单曲。
- 单曲与遗留不重叠；单曲页只显示「未被任何索引歌单引用」的那部分。

### 3. 策略 A：自动流程不删文件

- 移出本地索引、同步清理 D，都只解除归属，不删任何音频。
- 清理是显式动作：在「单曲下载 / 遗留歌曲 / 全部下载」页多选删除（两次点按确认）。
- 这与 [`下载引擎.md`](下载引擎.md) 的「用户主动下载永久保留，只在用户删时消失」一致。

## 四、边界与已知取舍

1. **升级前的文件**没有归属标记，默认按 `user` 处理：移出索引后落「单曲下载」而不是「遗留」。
   无法区分它们当初是不是为某个歌单下的；按用户资产优先。
2. **远端歌单 404 / 被删**：拉取失败，索引与文件都保留；用户可手动移出索引。
   从本地下载进入详情页的「删除」会先删远端、成功后再清本地索引并删掉会变成孤儿的文件，
   不会留下指向已删歌单的陈旧索引；云端删除失败时本地不动。
3. **手动删除歌单内已下载歌曲**：文件消失，该曲立即回到 A（远端有、本地没有）；
   再点「同步」会把它重新下载。若不想它回来，需要把它从远端歌单移除，或把歌单移出本地索引。
   自动拉取（启动时）只更新远端快照，不会下载。
4. **在播/在队列的歌**：删除是用户显式动作，沿用旧下载页语义（文件删、播放 fd 照常到段尾；
   队列来自本页时同步移出）。自动流程不删文件，因此不会命中这个问题。
5. **存储管理「清空已下载」**：清文件 + 下载元数据 + 本地库 + 归属标记；**保留歌单索引**
   （订阅关系还在，可重新下载）。
6. **歌手头像**：本地索引不存歌手头像，所有本地页面统一走「真头像优先、代表专辑封面兜底」，
   两类图使用不同缓存键，避免在线头像与本地兜底互相顶掉。实现入口见
   [`../src/utils/artistavatar.js`](../src/utils/artistavatar.js)：
   - 真头像：缓存键 `arp<歌手id>@60`（列表）/ `@200`（详情）；URL 落盘到
     `store/artist_meta.json`，来自 `/api/artist/head/info/get`。搜索结果歌手行也用 `arp<id>@60`。
   - 兜底图：代表专辑封面（发行时间最新且有封面），缓存键 `al<专辑id>@60/200`，
     与专辑页共用；下载完成时已预热，离线可直接命中。
   - 下载完成后的头像预热是**尽力而为**：异步、按歌手去重、限 64 位、连续失败 2 次即停，
     不阻塞下载，切后台/退出会中断。没跑完时列表显示兜底封面，不会空白。
   - 详情 `@200` 不随下载预热，在线打开歌手页时才取；下载后**没联网看过详情**就离线打开，
     详情大头像会退到同一张专辑封面（列表的 60 真头像仍可用）。
   - 旧版本写下的 `ar<id>@120/200` 不再被读取；要彻底清掉用存储管理的「清空封面缓存」。
7. **「下一首播放 / 收藏到歌单」**：上下文菜单设计稿里有，但当前播放器没有「插入下一首」API，
   本页多选暂只提供删除（遗留页另有保留为单曲）；接入前不要写成已实现。
8. **跨设备宽度**：项目按 S7 的 1020×240 设计，vh 只跟随屏幕高度，不代表宽度自适应。
   本功能的横向尺寸尽量用百分比 / flex（总览卡 23%（同首页文字卡）、专辑卡 23/31/47%、索引行全宽），
   专辑默认列数还按 `$falcon.env.screenWidth` 选；但 `SongRow` 的歌手/时长/标记列仍是
   固定 vh，换到明显更窄或更宽的设备上需要单独做一次响应式评审，不能只靠这几页保证。
