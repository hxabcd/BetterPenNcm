# 播放与定位能力

播放器对外统一走 `playFile(locator, positionMs, rate)`（项目封装，见 [`src/utils/player/sound.js`](../src/utils/player/sound.js)）；封装内部固定 `interruptPowerOff=true`、`reportPosition=true`，再调原生 `SoundPlayer.playFile(fileName, positionMs, rate, interruptPowerOff, reportPosition)`。原生签名见 [`运行时API参考.md`](运行时API参考.md) 第 4 节。

## 一、当前播放路径

- **有本地缓存**：`playFile(本地路径, pos, rate)`，秒开。
- **无本地缓存**：先取直链，`playFile(直链, pos, rate)` 流式起播；重连发 `Range: bytes=<offset>-` 拿 206，从指定位置继续。
- **直链取不到**（受限/网络失败）：回退「等缓存」路径（`needLocal`）。
- 播放的同时后台做**播放缓存**（落 `cache/`，按播放音质、受缓存上限 LRU），不是用户下载；不要承诺「后台继续下载」——切后台后脚本执行会被冻结。

## 二、定位、续播、倍速

- 平台**没有 pause / seek**：暂停 = `stop()`；续播/拖动/改倍速 = `stop()` + `playFile(locator, 新位置, rate)`。
- `position` 与 `rate` 对 URL 同样生效：实测从 60s 起播拿到 206（`Range` 字节位置与时长比例吻合），1.5 倍速下位置按 1.5 倍推进。
- 起播需要重新建流/缓冲，不是本地文件那种即时跳转；连续拖动进度条会频繁重拉流，体验取决于网络与 CDN。
- `playMediaSection(paramDataJson)` 的字段名是 **`fileName`**（不是 `url`）：`{fileName, position, endPosition, playBackRate, isInterruptPowerOff, reportPostion}`。实测 `endPosition=4000` 时位置停在 4000ms 不再推进（自动停）。当前播放器**未使用**它，统一走 `playFile`。

## 三、事件与进度

- 事件必须用信号对象 `.on(cb)` 订阅，**不能用属性赋值**；`playFile` 的 `reportPosition=1` 才会持续上报位置。
- SoundPlayer 是全系统单例，事件全服务广播：必须按 `playFile` 返回的 uuid 过滤，避免收到别的播放任务的事件。
- 位置事件约每 50~60ms 一条；播放器用「原生 position 事件锚定 + 墙钟插值」显示进度，500ms tick 输出。
- 事件实参（当前固件实测）：
  - `mediaPlayerPositionChanged(uuid, ms)`
  - `mediaPlayerDurationChanged(uuid, ms)` —— **周期性重复上报**（与位置同频）；`player.js` 的 `onDur` 只在值与现值相差 >500ms 时才 `emit/persist`，重复值无副作用
  - `mediaPlayerEndChanged(uuid)` —— 单参
  - `mediaPlayerEndWithErrorChanged(uuid, code, sub, msg)` —— `stop()` 时也会派发
  - `mediaPlayerProgressChanged(uuid, n)` —— 语义未明（0/4 等小整数），不参与逻辑
- `DurationChanged` 回填时长；`EndChanged` 是播完的精确信号，与墙钟判定共用 `requestEnd` 去重。
- `stop()` 触发的 EndChanged / EndWithErrorChanged 由播放器守卫忽略：`startSource` 在 `stop()` 前清 `uuid`、置 `paused=true/isPlaying=false`，事件回调第一道就返回。改动事件处理时保留这道守卫。

## 四、后台行为

- 应用切后台后 JS 会被冻结，不能依赖定时器继续跑下载或自动连播。
- 应用退出后无后台，会直接关闭；不要承诺后台下载或后台连播。
- 需要持续执行的任务（下载、缓存补齐）必须在应用前台时完成。

## 五、未实施/待验证

- `playMediaSection` 的段播放能力未接入播放器；接口已实测（见上），若接入先与 `playFile` 做接口归一。
- 连续拖动进度条的体验（每次 stop + 重起播）未系统验证。
- 无损/Hi-Res 档（v1 接口 `level=lossless|hires`，等价于原 `br=999000`）：带黑胶 cookie 实测可拿到 flac（24bit 曲目 `br≈1.8M`/51.8MB，STREAMINFO 48kHz/24bit；普通无损曲目 `br≈0.8M`），无权益或曲目无高码资源时回落 mp3/320k。FLAC 可播性用自建 Range 源验证（见 运行时API参考 第 11 节）。
