# 页面导航（逻辑页 + 实例槽位）

本项目所有页面跳转走 `src/utils/nav.js`，页面代码只写**逻辑页名**。本文说明平台导航模型、导航层的做法与协作规则。

## 一、平台导航模型（实测结论）

设备端 `libfalcon.so` 的 `FalconApp::launchPage` 反汇编 + 设备端 `jsfm-nvue` 生命周期分发实证：

- 一个 page key 在 app 内只有**一个实例**，页面栈保存的是实例序列；
- `navTo(key, params)` 命中**已在栈里**的 key 时：把该页上面的页面**全部销毁**（逐页 `FalconPage::autoPop()`，默认开启），把旧实例挪回栈顶，只补发 `onNewOptions` —— **不重新挂载**；
- `navTo` 命中**当前页**时：栈不动，只原地补发 `onNewOptions`；
- `finish()` 关闭当前页，露出栈里前一个页面。

即平台的 `navTo` 是「回到 / 重进那一页」，不是「再开一层」。若页面代码按标准 push/pop 写（mounted 读参数、返回用 `finish()`），直接用平台语义会出现**层级退回**：目标页恰好已在栈里时，中间层被销毁、旧实例参数不更新，返回落错层。

## 二、本工程的导航层

`utils/nav.js` 把「逻辑页」映射到多个**实例槽位 key**，`go()` 每次挑一个当前不在栈里的槽位再 `navTo`，于是平台必然走「新建实例」分支 —— 得到真正的 push；返回 `finish()` 就是 pop，调用页不会被销毁。

- **逻辑页名**：app.json 里该 .vue 的基础 key（`index` / `playlists` / `list` / `player` / `songinfo` / `album` / `artist` / `queue` / `settings` / …），也就是页面代码唯一需要知道的名字。
- **槽位 key**：同一 .vue 在 app.json 里的别名 key（`list2` / `list3` / …），只编译成几百字节的 re-export 模块；页面的 `$page.$pageName` 会是具体槽位 key。
- **槽位数**（`utils/nav.js` 的 `PAGES` 表）：按「可能同时存活的不同视图」估计。`list` / `songinfo` / `album` / `artist` 各 6 层（artist↔album、songinfo↔artist 是很容易堆深的循环），`playlists` 4 层，`queue` / `plinfo` / `dltracks` 2 层，其余页面 1 层。重复视图也各占一层（标准 push 语义），因此高频往返的页给得多。
- **目的地页**：`player`（以及根页 `index`）标 `reuse: true` —— 已在栈中时按平台语义回退到它（点行为「回播放页」，不叠第二层播放页）。
- **连点合并**：同一逻辑页 + 同一参数在 500ms 内重复 `go()` 只生效一次（日志 `dup-ignore`）。S7 交互慢，「点一下没反应再点一下」很常见；旧平台语义第二次是复用不会叠层，新语义下不合并会让同一页真叠两层。
- **槽位耗尽**：正常流程不应出现，但「歌手↔专辑 / 歌曲详情↔歌手」这类页面互跳循环理论上可堆到耗尽（按调用图 + 槽位上限枚举，理论最长合法链约 28 层）。此时复用**最上层**的同类实例（平台只弹掉它上面的页面，代价最小），日志 `degrade` 记录目标槽位；代价是页面 mounted 已读过旧参数，内容可能不是最新 —— 属异常路径，出现就加槽位/收缩链路。

参数通道：真机 `navTo` 参数不可靠，仍走本模块 pending 记录（按**槽位 key** 记账，另按逻辑页名兜底）；pending 覆盖式、不消费，兼容「页面会挂两遍」。页面在 `mounted` 里用：

```js
const p = paramsFor((this.$page && this.$page.$pageName) || '<逻辑页名>', this.$page ? this.$page.options : null)
```

实例记账：`App.onPageLifeCycle` 把每个页面的 `load / newOptions / show / hide / unload` 转给导航层（主通道）；`pageFrameMixin` 挂载时 `attachPage()` 兜底（只认页面根实例，按 page 对象身份幂等）。页面销毁（`finish`、返回或平台弹层）时槽位自动释放。

pagebus（跨页业务事件）改为**注册栈**：由页面栈上层优先处理，实例销毁后事件回落给下层页面。

## 三、页面代码规则

1. 跳转一律 `go('<逻辑页名>', params)`；**不要**直接 `$falcon.navTo`、不要写槽位 key、不要写变量页名（静态自检要求字面量，菜单表驱动的跳转用字面量分支）。
2. 返回一律 `this.$page.finish()`（`pageFrameMixin.onBack` 的默认实现）。
3. 参数在 `mounted` 里用 `paramsFor(真实页名, options)` 取一次即可；**不再有** `onPageParams`（复用页接新参数）—— 导航层保证每次跳转都是新实例。
4. 页面不要依赖「自己是否被复用」；需要刷新时用现有机制（pagebus 事件、`$page.on('show')`、播放器等单例订阅）。

## 四、新增页面 / 调整层级

1. 新建 `src/pages/<name>/<name>.vue`，根节点 `<page-shell>`，混 `pageFrameMixin`（左栏返回/上下文键）。
2. `src/app.json`：注册基础 key（必须与逻辑页名同名）→ `pages/<name>/<name>.vue`；若该页可能被叠多层，再注册槽位别名 key（`<name>2`、`<name>3`…，指向同一 .vue）。
3. `src/utils/nav.js` 的 `PAGES` 登记逻辑页与槽位列表（`slots[0]` 必须同名）；全局目的地页加 `reuse: true`。
4. `python scripts/theme_verify.py`：第六道会交叉校验「逻辑页 / 槽位 / app.json / 所有 `go()` 调用点」，构建前必须通过。
5. 真机验证：`bash scripts/nav_selftest.sh`（探针构建，独立 appid，不碰正式应用数据）。

## 五、调试

导航层日志（`[nav]`，走 logserver）：

```
[nav] go <逻辑页> -> <槽位> (push)          # 正常压栈
[nav] go <逻辑页> -> <槽位> (reuse)         # 目的地页回退（player）
[nav] go <逻辑页> (dup-ignore: Nms 内连点)  # 连点合并（同一逻辑页 + 同一参数，500ms 内）
[nav] go <逻辑页> (degrade: 槽位耗尽 → 复用最上层同类实例 <槽位>；…)   # 异常：槽位不足
[nav] page-load <槽位> live=<n> [<栈>]
[nav] page-unload <槽位> live=<n> [<栈>]
[nav] page-options <槽位>                   # 被平台复用的页面（player；degrade 也可能出现）
```

- 真机自测：`bash scripts/nav_selftest.sh`（探针页内串行 go/close，断言 `[nav]` 日志里的 push/reuse/unload、栈快照、15 层深度压力与 12 层内存采样；截图 `shots/nav_selftest.png`）。
- 构建期自检：`python scripts/theme_verify.py` 第六道。

已知边界：真机探针自测到 **15 层同时存活**仍正常（无平台弹层/加载失败；12 层时页面组件树约 4.1MB，进程 arena 另计，见 `scripts/nav_selftest.sh` 的深度压力场景），更深的平台上限未探到。典型使用混合浏览歌手/专辑/歌曲详情可到 10~16 层；若日志出现**非预期 `page-unload`**（被动销毁）或 `degrade`，需收缩链路或加槽位。
