# 存储层：数据落在哪、各走哪条通道

本文说明 BPN 的数据布局与写入通道。布局本身由 [`存储重构.md`](存储重构.md) §2 定义，
[`../src/utils/paths.js`](../src/utils/paths.js) 是路径的唯一真源 —— 本文不复述路径清单，
只讲「为什么这样分」与「写进去的代价是多少」，两者都是改存储相关代码前必须知道的约束。

## 一、两类写入通道

| 通道 | 实现 | 单次代价 | 用在 |
|---|---|---|---|
| **原生 `fs.readFile`** | 平台模块，不分叉 | µs 级 | 所有读 |
| **shell 重定向**（`printf` + `mv -f`） | 一次 `process.exec` = 一次 fork（≈50ms） | 与内容大小有关，与库规模无关 | 所有写 |

平台 `fs` 模块**没有写入接口**（只有 `exists/stat/statfs/readdir/readFile/mkdir/rm`），
`global.createFile` 也只建空文件。所以任何落盘都必须走 shell，写文本的封装是
[`../src/utils/fsutil.js`](../src/utils/fsutil.js) 的 `writeTextFile`：

- **原子替换**：先写 `<path>.tmp`，再 `mv -f` 覆盖，读到的永远是完整一版；
- **分片**：`/bin/sh -c` 的整串命令是**一个 argv**（Linux 单参数上限 128KB），
  按「转义后的字节数」在 60KB 处分片，每片一次 exec，最后一片带 `mv`；
- **合并写**：同一文件一条串行队列、一次在飞，期间来的新版本顶掉旧版本只落最新一版。

因此本层的核心取舍是**把 fork 次数压到与「改动了多少条数据」无关、而不是与「库有多大」成正比**。
这就是下面两个决定的来源。

## 二、为什么索引是 SQLite 而不是一堆 JSON

旧实现是「一张表一个 JSON 文件、整表读写」：写任意一条都要重写整份文件（一次 fork + 62KB 写）。
而设备上 `/usr/bin/sqlite3` 是 3.39.2，单行 `upsert` **一次 fork、代价与库规模无关**，
正好对上「条目多、单条小、按 id 增删改」的曲目/歌单/歌手索引。

访问模型固定为 **boot 整表灌内存 + 写穿**：`open()` 时一次导出各表到内存，此后所有查询都在内存里
（与旧 JSON 的读路径同速、不分叉）；写走单条 upsert、一批改动包在一个事务里。
所以本层**不得**出现在任何轮询/高频路径上。

「为什么大表是 db、小快照仍是 JSON」「封面为什么单尺寸」「歌词为什么不转 `.lrc`」三个结论
和它们的完整依据都在 [`存储重构.md`](存储重构.md) §0 与 §1，本文不重复。

## 三、顶层只剩 4 个 JSON + 索引库

```
data/
  config.json     应用配置      cookie.json   登录 Cookie
  state.json      播放会话快照    history.json  播放历史
  local_index.db  SQLite 索引库
  downloads/  cache/              每 track 一个目录（见 存储重构.md §2）
```

四个 JSON 是「每 5~15 秒整份重写」的小块（播放位置、播放历史）与两份单例配置，
体积小、写频次高，保持一个 key 一个文件后单次写的代价只与这条数据本身有关。
旧的 `storage/`（`preferences.json`）与 `store/`、`lrc/`、`covers/`、`music/` 目录
**不再创建**；升级时由 [`../src/utils/migrate.js`](../src/utils/migrate.js) 一次性搬过来，
旧目录保留不删（见 [`存储重构.md`](存储重构.md) §4）。

## 四、失败语义

**只有文件是真相**，没有第二份兜底：

- 写失败只记日志，不抛。内存里的数据仍在，下一次写会重试（`fsutil` / `db` / `store` 都是这个约定）。
- 索引库可丢：`sqlite3` 不可用时降级为空库，上层按「没有本地索引」降级显示，
  索引能从文件与网络重建 —— 这比「整个应用起不来」好。
- 文件系统是唯一事实：任何「索引说有、文件却没有」的状态都不维护，列表一律以实际扫描为准。

## 五、什么时候需要再考虑换方案

- 出现「一次写要在 50ms 内完成、且不能 fork」的新需求（当前没有：唯一的高频路径是播放进度快照，
  它整份只有几百字节）；
- 或索引规模涨到「整表灌内存」本身成为启动瓶颈（当前 `open()` 是一次导出 + 内存字典，
  实测规模为几百首量级）。

`fs.stat` / `fs.exists` 是原生调用、**不 fork**，轮询（如下载进度）只能用它，不能用 exec ——
这条约束见 [`下载引擎.md`](下载引擎.md) 的三条死线。

## 六、核对

```bash
D=/userdisk/secondary/miniapp/data/mini_app/pkg/8000200708310039/data
adb shell "ls $D; ls $D/downloads | head; sqlite3 $D/local_index.db '.tables'"
```

预期：顶层 `config.json cookie.json state.json history.json cookie.txt local_index.db downloads/ cache/`；
`sqlite3 .tables` 列出 `album artist track track_artist playlist playlist_track`。
