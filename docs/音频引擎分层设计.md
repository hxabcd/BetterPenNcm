# 音频引擎分层设计（重构提案）

> 状态：设计稿 + 骨架代码。`src/services/player/engine/` 下三个文件已落地但**没有被任何代码引用**，
> 不进产物、零风险。接线按 §4 分四步走，每步都能单独上线。
> 目的：让「音频实现优雅」这件事**不依赖换后端**——先把平台怪癖收进一层适配器，将来要换 aplay 只是多一个适配器。

---

## 1. 现状：不优雅的地方不在声音，在纠缠

`player.js` 1408 行 / 48 个函数 / 26 个模块级 `let`，其中：

| 指标 | 数量 | 含义 |
|---|---|---|
| `my !== gen` 手工对账 | 13 处 | 每个 `await` 之后都要自己对一次代次 |
| `emit()` 调用 | 34 处 | 任何改动都能直接推快照 |
| `persist()` 调用 | 18 处 | 落盘散落在业务分支里 |
| `paused = ` 赋值 | 11 处 | 同一个变量既是「用户暂停」，又是技术性保护位 |
| `startSource()` 调用 | 6 处 | 起播路径在 playAt / reopenAt 里各写一遍回退链 |

五条具体症状，按「改起来最值」排序：

### 1.1 `paused` 被借用作保护位（`player.js:503-528`）

`startSource` 第一件事是 `paused = true; isPlaying = false; uuid = ''` —— 这不是用户暂停，
是为了让自己的 `stop()` 派发出来的 `EndChanged` 不被当成「播完」触发连播。
**语义位被技术需要占用**，是后面一堆「守卫」的源头。

### 1.2 结束事件的语义靠猜（`player.js:207-226`）

```js
if (!durationMs || positionMs >= durationMs - NEAR_END_MS) requestEnd()
else { hint = '播放中断' }   // 认定是别的应用抢了单例
```
平台没有「谁发起的停止」这个概念，只能靠「是否临近结尾」反推。这个猜测本身没错，
错在它写在业务状态机里，而且和 `uuid`、`isPlaying`、`paused` 三个状态位耦合在一起判断。

### 1.3 事件实参靠容错解析（`player.js:136-160`）

`pickUuid` / `lastNum` / `firstShape` —— 因为 `duration`/`end`/`error` 的实参形状没实证过。
平台不确定性直接长在核心逻辑旁边，改一次事件处理要重新想一遍这些都是什么。

### 1.4 时钟状态四个变量手工同步（`player.js:471-495`）

`baseMs` / `startedAt` / `rate` / `positionMs` 由 `startSource`、`onPos`、`startTimer`、`reopenAt`
各自维护；`elapsed()` 必须记得乘倍速。任何一处漏了就表现为进度跳变或提前判定播完。
`startTimer` 还同时干三件事：时钟推进、播完兜底、快照节流。

### 1.5 两条几乎重复的回退链（`playAt:777` / `reopenAt:646`）

「直链失败 → 等缓存 → 本地起播」在 `playAt` 和 `reopenAt` 各写一遍，`startSource` 调 6 次，
每处都要自己 `my !== gen` 对账。这不是坏代码，是**缺少一个「拿到可播地址」的单一出口**。

## 2. 目标结构

```
pages/*.vue
   │  只读 snapshot、只调 player 的语义方法
player.js            状态机 + 对外 API（目标 ≤400 行）
   ├── queue.js      队列模型：原始队列 / 随机临时队列 / 双坐标 index
   ├── source.js     取到可播地址：本地缓存优先 → 直链 → 等缓存（唯一出口）
   ├── engine/       音频引擎端口（业务唯一依赖）
   │    ├── index.js        契约：EVENTS / END_REASON / 能力表说明
   │    ├── clock.js        进度时钟：baseMs+startedAt+rate 三变量收成一个对象
   │    └── soundplayer.js  SoundPlayer 适配器：吞掉 uuid/stop 回声/实参形状
   └── session.js    快照持久化（已有，不动）
```

职责边界一句话：
- `engine` 只管「出声」和「把它发生的事翻译成五种语义事件」；
- `source` 只管「这一秒该从哪里出声」；
- `player` 只管「现在应该播哪首、播完该播哪首、界面该显示什么」。

## 3. 三个核心抽象（骨架代码已实现）

### 3.1 能力声明，代替散落的平台判断

```js
export const CAPABILITIES = {
  pause: 'stop',    // 无原生 pause：暂停 = stop()，位置由上层记住
  seek: 'reopen',   // 无原生 seek：换位置 = 重新 open
  rate: 'native',   // playFile 第三参支持倍速
  volume: 'none',   // 无音量接口 → 只能走系统音量
  route: 'none'     // 无输出设备选择 → 蓝牙/喇叭由系统决定
}
```
上层写**一次**降级逻辑（`if (caps.pause === 'stop') …`），而不是在每个方法里重复
「这个平台没有 pause」。换后端时能力表换一份，业务不改。

### 3.2 会话令牌，代替手写的 `gen`

```js
const session = await engine.open({ locator, positionMs, rate })
if (session !== engine.sessionId()) return   // 晚到就作废
```
`uuid` 过滤下沉到适配器内部 —— 上层不再需要认识「SoundPlayer 是单例、事件全广播」这件事。

### 3.3 结束原因，代替语义猜测

```js
engine.on((ev, p) => {
  if (ev === EVENTS.ENDED) {
    if (p.reason === 'natural')     next()          // 连播
    if (p.reason === 'interrupted') remember(p.positionMs) // 被别的应用抢了
  }
})
```
「临近结尾」这个启发式仍然存在（平台不给 reason 就只能这么判），但**只在适配器里写一次**，
并且 `stop()` 的回声由适配器用时间窗吞掉，上层不再需要 `paused` 兼职保护位：

```js
// 现在（player.js:503）
paused = true; isPlaying = false; uuid = ''; stopTimer(); await stop()

// 之后
await engine.open({ locator, positionMs, rate })   // 破坏性语义在端口文档里就写明了
```

## 4. 迁移四步（每步独立可上线）

### Step 0 · 给 sound.js 加多播（15 行，不动旧路径）

现在 `sound.js` 只有一个 `handlers` 槽位且已被 `player.js` 占用，适配器无法另订阅。
追加订阅数组，两条路径并行分发：

```js
// sound.js
const listeners = []

/** 多播订阅：fn(name, args)。返回取消函数。与 bindEvents 并存（旧路径不受影响） */
export function subscribe(fn) {
  listeners.push(fn)
  let off = false
  return function () {
    if (off) return
    off = true
    const i = listeners.indexOf(fn)
    if (i >= 0) listeners.splice(i, 1)
  }
}

// wireIfReady 里的包装改为：旧 handler + 多播
sig.on(function () {
  try { h.apply(null, arguments) } catch (e) {}
  for (let i = 0; i < listeners.length; i++) {
    try { listeners[i](n, arguments) } catch (e) {}
  }
})
```
验收：真机跑一遍播放/暂停/切歌，`player.js` 行为零变化。

### Step 1 · 接时钟（`engine/clock.js` 已写好）

`baseMs/startedAt/elapsed()` 换成 `const clock = createClock()`：
- 起播：`clock.reset(pos)`
- 收到 position：`clock.anchor(ms)`
- 改倍速：`clock.setRate(r)`（内部先快照，进度不跳）
- 显示：`clock.now()`
- 暂停：`clock.stop()`

验收：0.5x / 1x / 2x 下拖动进度条，进度不回跳；播完时刻误差与原实现一致。

### Step 2 · 抽队列（`queue.js`，尚未写）

把「原始队列不重排 + 随机临时队列 + index 指向哪个」收成一个对象，
`removeFromQueue` / `insertNext` / `buildShuffle` / `switchTo` 里的双坐标运算全部内聚。
对外只有 `list() / current() / index() / setIndex() / remove(ids) / insertNext(songs) / shuffle(on)`。
这是**最大的一块**（`player.js` 里约 300 行），建议放最后做，前两步已经能拿掉大部分痛感。

### Step 3 · 接引擎（`engine/soundplayer.js` 已写好）

1. `import { createSoundPlayerEngine, CAPABILITIES } from './engine/soundplayer.js'`
2. 删掉 `bindEvents({...})` 与 `onPos/onDur/onEnd/onErr/onProg/pickUuid/lastNum/firstShape`
3. `startSource` 改成 `await engine.open(...)`，返回会话令牌替代 `my !== gen`
4. `paused` 只表示用户暂停，不再作为 `stop()` 的保护位

验收见 §5。

## 6. 这套重构和「要不要换后端」的关系

换后端（`ffmpeg|aplay`）唯一能拿到的是 **音量 + 输出设备路由**；
它的代价是 ALSA 独占（固件无混音服务）、子进程回收、熄屏行为、失去 TTS 与 `interruptPowerOff`。

这套分层的意义是：**先让「换」变成只写一个适配器**。

- 现状：换后端 = 重写 `player.js` 里 6 处起播链、4 处事件猜测、11 处 `paused` 语义
- 分层后：换后端 = 新增 `engine/aplay.js`（实现同一个端口），`CAPABILITIES` 改成
  `{ pause: 'stop', seek: 'reopen', rate: 'native', volume: 'native', route: 'native' }`，
  `player.js` 一行为此改动

所以建议的顺序是：**先分层（Step 0-3），再按实际需求决定要不要加第二个适配器**。
如果分层做完，发现蓝牙/音量仍是刚需，那时接入 aplay 只是一天的工作量，而不是一次重构。
