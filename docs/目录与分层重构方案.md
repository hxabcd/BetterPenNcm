### 1.3 平台与工具链约束（硬边界）

三条平台事实决定重构的可行域（file:line 证据见附录 A）：

1. **页面装载按 key，不按路径**：运行时按 app.json key 动态 `import(<key>.js)`；挪 .vue 只要 key 不变，运行时装载与 chunk 划分不受影响（chunk 成员按引用图切分）。
2. **SFC 不能 re-export**：`.vue` 没有转发导出——任何组件/页面移动都必须同步改所有 import 它的文件，没有「过渡期双路径」。
3. **脚本路径硬编码点多**（§3c 清单）：theme_verify.py CHECKS 表 ≈45 文件精确路径、perf_selftest.mjs 30 个 rel path 键、gen_tokens.py 双端路径、build.sh 生成物写入路径、storage/media_selftest 的 utils 子树假设。挪文件必须同步这些清单。

## 2. 目标结构

### 2.1 设计原则

1. **路径 = 分层**：目录名直接表达「平台适配 → 基础设施 → 业务域 → UI 辅助」，import 只允许向下。
2. **一目录一主题**：公共 API 面大的模块（theme 31 / log 28 / frame 22 / tokens 19 / nav 18 / rail 17）是分层锚点，位置必须语义明确。
3. **零行为变化**：每阶段都是纯移动/重命名/收敛重复，产物运行行为不变（构建号与编译期 hash 除外），真机无感。
4. **方向靠自检锁住**：分层最终由 theme_verify.py 第七道硬校验（§5），不靠自觉。

### 2.2 分层轴与依赖方向规则

```
pages/       参数解析 + 视图组装 + 动作分派
  ↓ import
components/  展示组件（chrome 外壳 / 域组件 / 播放页子面板）
ui/          UI 辅助层（mixin / 令牌 / 分页 / 可见性 / 选择集）
services/    业务域层（ncm / player / cover）
core/        平台适配 + 应用基础设施（platform/ + infra/）
assets/ styles/ vendor/   资源（不 import 业务）
```

依赖规则（第七道按此校验）：

- **R1** `pages → {components, ui, services, core}` 允许。
- **R2** `components → {ui, core, assets, vendor}` 允许；**components/chrome/ 追加禁止 import services/**（chrome 是跨应用框架候选，域组件不在 chrome）。
- **R3** `ui → {core/infra, assets}` 允许；**禁止 ui → services、ui → components**。当前违例 ui/multi.js:16 在 §6.3.3 处理。
- **R4** `services → {core, services}` 允许；跨 services 子域优先经门面（download.js 已是 player 域门面）。
- **R5** `core → core` 只允许 infra→platform 方向；禁止 core 反向引 ui/services/components/pages。
- **R6** db.js 归 core/platform（sqlite3 通道），但域表 DDL（track/artist/album/playlist 等九张表，db.js:51-120）留在 db.js 集中、文件头注明每张表的所有者域；services 侧经 store/media/域存储模块访问。这是**明确的妥协**：DDL 集中可审计 > 目录纯度。

### 2.3 关键约束的处理

- **import 改写量**：全工程 665 处相对 import（动态 import 全是裸模块，零波及）。可脚本化（§3a），改完跑六道 + 构建冒烟。
- **不引入 `@` 别名**：构建器虽内建 `@`→src（rollup.config.js:77-82），但全工程 0 处使用。保持全相对路径——相对路径的 `../` 数量是依赖跨度的视觉信号（跨轴 import 长而显眼，恰是想要的）。风格不混合。
- **页面目录不分组**：22 页保持 `pages/<key>/<key>.vue` 同名约定。key = 目录名 = nav.js PAGES 键 = app.json key = 槽位 key，五处同名是导航层稳定性的基石；`src/pages/*/*.vue` 单层 glob 校验也依赖它。收益 < 约定破坏成本。
- **生成物路径**：buildInfo.js / logconfig.generated.js 移入 core/infra/ 后，build.sh 写入路径与 .gitignore 锚点（.gitignore:15-17）同步改。

- **mixin 集中的收益**：theme_verify.py 第四道 MIXIN_SOURCES 从 6 个分散路径变 1 个目录 glob，后续加 mixin 只登记一处。
- **components 分组的依据**（探索实证）：player/ 5 组件只被 player 页消费；rows/cards 内 6 个组件单一消费者；chrome 10 组件被多页共享——分组即使用边界。

- **UI 架构不变**：mixin 机制、page-shell 约定、令牌生成链、nav 层契约全部原样；本方案是目录与模块边界的归位，不是 UI 架构重设计。
