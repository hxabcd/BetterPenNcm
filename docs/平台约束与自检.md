# 平台约束与自检

本文只收「构建期不报错、运行时才炸」的平台坑，以及对应的自动检查。改主题、页面结构、模板绑定或视觉常量前先读。

## 一、最阴的一类 bug：用了但没 import

JS 引用未导入的标识符时，构建期不报错（编译器按全局查找处理），照常出包；如果出错点在 `data()` / render 里，整个页面组件创建失败，表现为整页黑屏。

`scripts/theme_verify.py` 第二道检查：扫描下列 16 个符号，在 `<script>` 段里用了却没出现在 import 里就报错（先剥掉注释与模板）：

```
currentBg  currentAccent  currentAccentKey  bindTheme  unbindTheme
setBg  setAccent  accentMixin  aIcon  fgIcon  ACCENTS  PRESETS  currentKey  ICON
railBack  railBtn
```

## 二、平台渲染硬约束

### 样式

| 约束 | 说明 |
|---|---|
| 只认**单类名**选择器 | 嵌套/复合选择器无效；状态与动态色一律走内联 `:style` |
| LESS 变量是编译期的 | 换色不能靠变量，必须运行时内联；共享的静态视觉常量走 `src/utils/ui/tokens.js` 与生成的 LESS 令牌段 |
| `<image>` **不能染色** | 颜色必须生成进 PNG 文件本身 |
| `position:absolute` 的定位基准 | 浮层基准是 `.psh-body`（只盖内容区、不盖左栏）；贴底浮窗用 `bottom` |
| `top` / `left` / `right` / `bottom` | 当前固件实测四个方向均可用（含 `left` + `right` 拉伸）；浮层基准仍是 `.psh-body`，改动布局后截图核对 |
| `lines:1 + ellipsis` 节点**必须有确定宽度** | 别用 `max-width` 做「内容撑到上限」 |
| `text-decoration: line-through` 真机可用 | class 与内联 `:style` 都渲染（2026-10-18 探针实测）；按状态切换时用内联 |

### 动画与帧调度（2026-11-01 探针实测）

探针页（一屏 12 条跑道、同一节奏，**靠肉眼看「平滑 / 瞬跳 / 不动」**）完成使命后已移除，结论留档于下表。
`transitionend` 之类的结束事件在本平台
根本不触发（见下表最后一行），不能用来判定过渡是否生效。

| 能力 | 实测 | 结论 |
|---|---|---|
| `requestAnimationFrame` | 500ms 内回调 **0 次** | **完全不可用**，凡是「每帧推进」的逻辑都得换 `setTimeout` |
| `setTimeout(fn, 16)` / `setInterval(fn, 16)` | 稳定后 15~17ms；启动初期会抖（实测 67/651/223/45ms） | **可用**，但不能假设准时 —— 进度按墙钟算，别累加步长；关键状态另设低频兜底 |
| `transition` 写在**内联 `:style`** | 瞬跳（不插值） | **不可用** |
| `transition` 写在 **class（LESS）里** | 平滑插值 | **可用**（具体属性见下表） |
| 两个状态类来回切换（每类各自带 `transition` 和目标值） | 平滑插值 | **可用**（不必写内联） |
| `@keyframes` + `animation` 写在 class 里 | 平滑（可 `alternate infinite` 自动往复） | **可用** |
| `transitionend` / `animationend` | 任何写法都不触发 | **事件不可用**（别用它判断是否插值，只能肉眼看） |
| `Element.animate` / `createAnimation` / `$falcon.animate` | 都不存在 | 没有平台原生动画 API |

**各路径对具体属性的表现**（同一套跑道探针，逐条肉眼看「有中间态 / 硬切 / 完全不动」）：

| 属性 | class 内 `transition` | `@keyframes` | 两个状态类切换 | JS 逐帧写内联 |
|---|---|---|---|---|
| `transform` | 有中间态 | 有 | 有 | 有 |
| `background-color` | 有 | 有 | 有 | 有 |
| `opacity` | 有 | 有 | —（随 background-color 一类） | — |
| `left`（布局属性） | 有 | — | — | — |
| `font-size` | 硬切 | **整个动画不动** | 硬切 | **有中间态** |
| `color` | 硬切 | **整个动画不动** | 硬切 | **硬切** |

两条硬结论：

1. **`font-size` / `color` 没有任何 CSS 路径能平滑**。`@keyframes` 里写这两个属性会让**整条动画
   完全不生效**（属性被丢弃后没有可动内容）—— 别在 keyframes 里写字号/颜色。
2. 字号还剩下「JS 逐帧写内联 `font-size`」这一条路（会每帧触发文字重排，成本明显高于
   `transform` 补间）；**颜色连这条路也没有**，`color` 的高亮变化只能硬切。

⚠️ **`animation` 的时长是「单程」**：`animation: x 1.6s linear infinite alternate` 表示
0→终点用 1.6s、再终点→0 用 1.6s，一个来回 3.2s；拿它和「800ms 翻一次目标」的过渡并排比，
看起来会「慢一倍」—— 这是写法问题，不是平台差异。

经验规则：**要过渡就把 `transition` 写进 LESS class，内联 `:style` 只负责给目标值**；
`transition: all` 只对上面「有中间态」的属性有效。歌词面板的滚动走 JS 补间（`animateTo`）——
每 16ms 写一次 `transform`，不依赖任何 CSS 动画能力，窗口也能自己控制。

### 响应式

- 运行时用到的 data 字段**必须在 `data()` 里声明**——事后 `this.x = v` 不参与响应式。
- 跟播放进度同步变化、且要驱动渲染的量走 **`watcher → data`**；别挂多层 computed，依赖者收不到通知会停在首帧。

### 组件结构

- **含 slot 的组件模板结构要恒定**：别在组件内部用 `v-if` 增删/切换兄弟节点；平台渲染器在结构变过一次之后再补插 slot 会插错位。普通节点（不涉及 slot 补插）可以切换，例如 `login.vue` 的 pane 用 `v-if`。
- **页面级整体挂载/卸载**：在父页面用 `v-if` 整体切换「含 slot 的组件 ↔ 普通节点」实测正常（两种状态都能完整渲染）。约束针对的是 slot 组件**内部**的模板结构，不是组件本身的进出。
- **模板 `:x="x"` 是取字段，不是调用**：裸绑定的名字必须来自 props / computed / data（含 mixin 提供的）；来自 methods 会拿到函数，轻则静默失效，重则组件炸掉、整块 UI 消失。`theme_verify.py` 第四道按此硬判定。
- **页面写在 methods 里、但 mixin 已提供同名 computed 的成员会被静默丢掉**：Vue 的 `initState` 顺序是 methods → data → computed，`initComputed` 里 `if (!(key in vm))` 在存在同名 method 时为假 → 只 `warn` 不覆盖，`vm.xxx` 仍是 mixin 那份。`playlists.vue` 的 `rail()` 就这样整份失效过（左栏退回 mixin 的 `[返回]`，「创建歌单」键从未出现）。**改左栏一律写进 `computed`**；`theme_verify.py` 第四道对这种情况硬失败。

## 三、注册与导航

- 新页面必须在 `src/app.json` 的 `pages` 注册——不注册构建不报错，点进去断链。
- **导航统一走 `src/utils/nav.js`**（逻辑页 → 实例槽位）。页面代码只写**逻辑页名**（app.json 里该 .vue 的同名基础 key）：`go('list', params)`、`paramsFor(...)`、`this.$page.finish()`；**不直接 `$falcon.navTo`、不写槽位 key（`list2` 等）、不传变量页名**。
- app.json 里同一个 .vue 可以注册多个 key：基础 key = 逻辑页名，其余 = **实例槽位别名**（`list2`/`songinfo2`/`album2`…）。导航层 `go()` 每次挑一个当前不在栈里的槽位 key 再 navTo，得到标准 push/pop 语义；每个别名 key 各编译一份 `.falcon_/<key>.js.bin`，但只是几百字节的 re-export。
- 槽位表在 `utils/nav.js` 的 `PAGES` 里维护：`slots[0]` 必须与逻辑页同名；槽位数按「可能同时存活的视图层数」给（热点页 6 / playlists 4 / 部分 2 / 叶子 1）。`player` / `index` 标 `reuse: true`（全局目的地页，已在栈中时回退到它）；连点由 `go()` 合并（500ms 同逻辑页同参数），槽位耗尽才走 `degrade`（复用最上层同类实例，异常路径）。
- 平台 `navTo` 对已在栈里的同名页是「弹掉上层 + 复用旧实例 + 只补 `onNewOptions`」，不重挂载；旧实现里的 `onPageParams`（复用页接新参数）与手写别名 key 均已废弃，不要再引入。
- 新增/调整页面层级的完整步骤见 [`页面导航.md`](页面导航.md)；`theme_verify.py` 第六道硬校验逻辑页 / 槽位 / app.json / 所有 `go()` 调用点。

## 四、改完必跑的三项自检

```bash
python scripts/theme_verify.py
python scripts/gen_tokens.py
python scripts/gen_icons.py --no-fetch --check
```

三项都应以退出码 0 结束。各自判据：

### `theme_verify.py`（六道）

1. **片段检查**：`CHECKS` 表列出每个文件必须出现的实现片段；删/并文件后要同步这张表（否则第一道直接报文件不存在）。
2. **缺 import**：上面 16 个符号用了但没 import。
3. **mixin 契约**：页面接了 `multiSelectMixin` 就必须定义 `multiList()`；漏了不会报错，但「全选」永远按空范围算。
4. **模板裸绑定（硬失败）**：`src/pages` 与 `src/components` 下所有模板的裸标识符，必须由 props / computed / data 提供；只由 methods 提供即失败。判据按缩进把 mixin 与页面成员的 computed / methods / data / props 归组。同一道还查**页面 methods 与 mixin computed 同名**（页面那份被 Vue 静默丢弃，见「组件结构」末条）——判据只能看页面自己的分组，不能与 mixin 取并集。
5. **token 值字面量（硬失败）**：`src/{pages,components,styles}` 下不允许出现 token 的颜色值字面量；白名单是 `src/utils/ui/tokens.js`、`src/styles/common.less`（整文件）与 `scripts/gen_tokens.py`——`common.less` 的生成段之外目前也整文件跳过。只巡颜色不巡尺寸，避免与普通间距撞车。
6. **导航路由表（硬失败）**：`utils/nav.js` 的 `PAGES`、`app.json` 的页面 key、各页 `go()` 调用点三者一致——逻辑页必须有同名基础 key、槽位 key 必须注册且指向同一 .vue、app.json 不允许孤儿页、页面文件都要有注册；`go()` 第一参必须是已登记逻辑页的字符串字面量；源码里不允许出现旧别名 key（`songinfonested`/`artistlist`/`playlistpick`）、`onPageParams`、或 `$falcon.navTo` 直连（nav.js 除外）；`go('index')` 放行但视为违规（根页不是导航目标），settings 二级菜单表与 `openGroup` 字面量分支必须一一对应。

### `gen_tokens.py`

校验 `src/styles/common.less` 的 `@tokens:begin~end` 段与 `src/utils/ui/tokens.js` 的值表一致。改视觉常量：改 `tokens.js` → `python scripts/gen_tokens.py --write` → 再跑三项自检。

### `gen_icons.py --check`

校验 PNG 数量与 `src/assets/icons.js` 注册表是否与生成器逐字节一致。当前为 67 个 key / 120 个 PNG；`icons.js` 是纯生成物，手改会被拦下，用 `--emit-js` 重新生成。
