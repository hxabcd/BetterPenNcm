# 歌单接口边界与批量删除

本文记录网易云歌单接口的当前已知边界；实现见 [`src/utils/ncm/playlist.js`](../src/utils/ncm/playlist.js)。服务端行为会变，改动列表/删除逻辑前先按「复现方式」重测。

## 一、`/api/v6/playlist/detail` 单请求内联上限 = 1000 首

| 歌单 | trackCount | `n=50` | `n=1000` | `n=100000` |
|---|---|---|---|---|
| 我喜欢 | A | 239KB · tracks=50 | 1749KB · tracks=A | 1749KB · tracks=A |
| 订阅 A | B | 309KB · tracks=20 | 308KB · tracks=20 | 308KB · tracks=20 |
| 订阅 B | C | 1880KB · tracks=20 | 1881KB · tracks=20 | 1880KB · tracks=20 |

表中的 A/B/C 是匿名化后的 `trackCount` 变量，仅用于说明边界，不记录账号的具体数据。

- **`trackCount ≤ 1000`**：一个请求就能拿全曲目（A 首 → 1749KB，PC 有线约 512ms）。
- **`trackCount > 1000`**：服务端把内联强制砍到 20 首，加大 `n` 无效。
- 响应体积与 `trackCount` 相关：即使只内联 20 条，`trackIds` + 元信息也可能很大。
- 更大歌单只能走 `/api/v3/song/detail`，300/批；B 首 6 批 3.3MB / 约 2.5s（PC 有线），C 首推算 ≈37 批 / ≈24MB。

## 二、全选与批量删除

- 「全选整个歌单」做删除只需 **id**：首屏请求里的 `trackIds` + `addTimes` 已全量到手，不必预取全量曲目对象。
- 曲目列表页的「全选」因此走 **id 直选**（不拉全量对象）；只有点「下载」时才补 `/api/v3/song/detail` 取回选中曲目对象（见 `list.vue` 的 `toggleAll` / `doDownload`）。
- **点行起播的播放队列是整份歌单**（与「播放全部」同口径）：只加载了前 50 首时先拉全量、按 id 找回点中的曲目再起播；不能拿已加载子集当队列，否则连播/上一首/队列页都只在这 50 首里转。
- `op:'del'` 一次可传整个歌单的 id（实测 9335B，未发现条数上限）；传不存在的 id 仍返回 200，个别 id 失效不会让整批失败。
- 删除路径 `removeFromPlaylist` 只需 id 数组；客户端以本地选中集合为准收敛，不依赖回包。

### 坑一：`{code:404,'歌单不存在'}` 与 id 无关

404 的成因是**歌单本身不可操作**，不是 id 有问题。实例：已从 `/api/user/playlist` 消失、但按 id 仍能 `playlist/detail` 读到的旧歌单，传什么 id 都 404。

→ `cachedPlaylistRole` → `canManage` 的前置拦截是必要的，别删。

### 坑二：写操作必须走 weapi

读接口里的搜索/直链/歌曲详情用明文 `/api/`；歌单详情与曲目批量详情也走 `weapiPost`（路径由 `/api/` 转 `/weapi/`），登录与写操作（喜欢、加/删歌、歌单管理）同样走 `weapiPost`（`utils/ncm/weapi.js`）。旧的 `NeteaseClient._post` 写法已不在仓库中，不要照抄。

## 三、歌单详情页接口

| 用途 | 接口 | 参数 |
|---|---|---|
| 详情 | `POST /api/v6/playlist/detail` | `{id, n:0, s:8}`；返回 `description/coverImgUrl/subscribed/specialType/privacy/trackCount/playCount/creator` |
| 收藏（订阅） | `POST /api/playlist/subscribe` | `{id}`；重复订阅也 200 |
| 取消收藏 | `POST /api/playlist/unsubscribe` | `{id}` |
| 重命名 | `POST /api/playlist/update/name` | `{id, name}` |
| 删除 | `POST /api/playlist/remove` | `{ids: JSON.stringify([id])}` |
| 新建 | `POST /api/playlist/create` | `{name}` → `{code:200, id, playlist:{…}}` |

边界：

- **新歌单 id 取回包顶层 `id`**（`playlist.id` 同值）；回包的 `playlist.creator` 是 `null`，别从它取创建者。
- 建完**立刻**就能在 `/api/user/playlist` 里查到，也能立刻 `manipulate/tracks` 加歌 ——
  「添加到歌单」里的「新建并加入」因此是一步完成的（不必等列表刷新）。
- **歌单名按显示宽度卡 40**（CJK 记 2、ASCII 记 1），不是字符数也不是字节数。
  实测：20 汉字 ✅ / 21 汉字 ❌ / 40 ASCII ✅ / 41 ASCII ❌ / 18 汉字+4 字母 ✅ / 19 汉字+3 字母 ❌。
  空名与纯空格同样算超界。超限 → `{code:400,'标题字数异常，请修改'}`，
  客户端用 `fitPlaylistName()` 先截再发。
- **连续新建会被限频**：`{code:405,'操作过于频繁，请稍后再试'}`（间隔约 15s 才恢复）。
  客户端对 405 单独给「稍后再试」的文案。

- `playlist/subscribe` 的 `t` 参数无效；取消订阅必须走 `playlist/unsubscribe`。
- 重命名别用整包更新 `playlist/update`（404）；用 `playlist/update/name`。
- 删除别用 `playlist/delete`（400）；用 `playlist/remove`。
- 订阅自己的歌单 → `{code:401,'歌单创建者已设置隐私'}`；「我喜欢」specialType=5，服务端不许改名/删除。
- 订阅歌单不能加/删歌（401）；客户端只对自己创建的 +「我喜欢」显示管理入口。

## 四、测试安全约定

所有写测试必须可回滚：测试 id 取自「我喜欢」并先减去目标歌单现有 id，操作末尾回读确认歌单未变；账号数据不留痕。探针脚本含账号态，不随仓库发布。
