# 调试与设备操作

设备侧的取日志、排查、探针与传输层契约。改脚本或上设备前先读；平台行为本身见
[`平台约束与自检.md`](平台约束与自检.md)，构建/装机命令见 [`../AGENTS.md`](../AGENTS.md)「常用命令」。

## 一、设备传输层（`scripts/lib/device.sh` 适配层）

设备操作的实际执行层是工作区工具链：bash 脚本经 `scripts/lib/common.sh` 载入 `scripts/lib/device.sh`
（本项目自己的**适配层**：只保留旧的 `dev_select <mode>` 位置参数形态与 `BPNCM_*` 变量名，再翻译成共享层参数）
→ `tools/dictpen-dev/lib/project.sh` → `tools/dictpen-dev/lib/transport.sh`（bash 兼容层）；
`devctl` CLI 走 `dpd/transport.py`，两套行为等价（对拍见 `test/test_transport_parity.py`）。
连接方式由 `tools/dictpen-dev/config.toml` 决定，**脚本与命令行都不指定 adb/ssh**。

脚本内用五原语 `dev_run` / `dev_put` / `dev_get` / `dev_exists` / `dev_check`，契约要点：

- `install.sh` / `build.sh` **不经过** device.sh：它们是薄壳（各 14 行有效代码，三份除注释外逐字一致），
  只 source `scripts/lib/dev.sh` 定位工作区后 `exec devctl install|build "$@"`；参数解析全在 devctl 侧
- 例外：`nav_selftest.sh` 的探针装机（`uninstall → put → install → start`，探针 appid）仍用自己的五原语序列
- **退出码不能判断成败**：adbd 不回传远程退出码，关键写操作用 `dev_exists` 事后校验
- 新建 `set -e` 脚本时顶层不要写 `[ -n "$X" ] && ...`：MSYS bash 5.3.20（agent 执行环境）在 source 链含 `.`
  命令时，顶层 `&&` 列表首命令失败会整脚本静默退出 rc=1；Git Bash 5.3.15 正常。统一 `if` 写法
- 别用外部 `timeout` 包 `dev_run` 等 shell 函数（timeout 是 exe，执行不了 shell 函数）

## 二、日志

- `console.log` **不进**设备日志 → 用 `core/infra/log.js` 的 `log()`（POST 回 PC 的 logserver）。
  排查前先确保 `python scripts/logserver.py` 在跑，**且本次构建注入了 `BPNCM_LOG_SRV`**；
  缺省是 127.0.0.1，在设备上连不通、**静默失败**（默认发布形态就长这样）
- 远程回归不受影响 —— 脚本抽的是系统日志里的 `console.warn`
- 崩溃排查：设备 `/data/applog/YD_PEN_APP.log`（框架层）+ `device_log.txt`（应用日志，**崩前最后一条即断点**）
- **被框架吞掉的页面异常**只显示 `console().error: null`；`app.js` 已常备 `App.onError` + 覆盖
  `$falcon.onAppError`，抛错以 `[app] onAppError: ...` 进日志
- 导航层排查：`[nav]` 日志（`go … (push|reuse|degrade)`、`page-load/unload`、`page-options`）走 logserver；
  返回落错层 / 页面被意外销毁时先看槽位与栈顺序，`bash scripts/nav_selftest.sh` 可跑 push/pop 自测。
  日志含义见 [`页面导航.md`](页面导航.md) §五

## 三、探针与自动化

- **探针版**：`bash scripts/build_probe.sh` 构建**独立 appid** 的探针版（入口 = `pages/probe`；
  脚本临时改 appid 后自动还原源码），安装/启动用产物的探针 appid，不卸载也不清空正式应用数据；
  用完 `miniapp_cli uninstall <探针appid>` 清理。探针日志同样走 logserver（构建时注入 `BPNCM_LOG_SRV`）；
  安装命令见脚本头部注释
- 平台能力动前（`global`、原生扩展、输入法、网络状态等）先用探针页验证，别在正式页里试

## 四、设备驱动与截图

- `miniapp_cli start` 的页名写**裸名**（带 flag 会被当成页面文件名 → 黑屏）；应用运行中页名同样生效
  （实测可直接切页）；`injectKey` 不驱动 UI，遥控走 `/tmp/bpncm_cmd.log`
- **截图用 `miniapp_cli capture`**（UI 合成画面，直接可看，无需旋转/分帧）；capture 跟随当前前台画面
  （切到其他应用后截到的是那个应用），应用切换瞬间可能拿到空白帧；**熄屏时返回空白帧**
  （`/tmp/.screen_state` 为 `screen_on=0` 即熄屏），截图前先 `adb shell hal-screen on` 点亮

## 五、链路与登录态

- **下载慢先查 WiFi 链路速率**（`iw dev wlan0 link` 的 rx bitrate）：这台笔须钉在 2.4GHz BSS，
  改配置走 `wpa_cli` + `save_config`，别直接编辑 `wpa_supplicant.conf`（会被回写覆盖）
- 设备保持已登录；登录态在 `$dataDir/state.db` 的 `kv` 表（`ncm_cookies` 行）与 `cookie.txt` 里，
  **日志/汇报中不要回显**
