# 文档与注释维护规范

本文规定如何编写、核验和清理项目文档及代码注释。目标是准确表达项目当前的行为与当前要求，不维护决策编年史。

## 依据规则

- **当前实现**：代码、配置、生成器及可执行检查说明程序现在如何工作。文档和注释是说明，不是实现事实的证明。
- **设备或外部行为**：使用当前环境下可复现的直接观察及原始结果。设备命令在脚本和多篇文档中重复出现，不构成多份独立证据。
- **当前意图**：以用户当前明确表达的要求为准，按原意和范围理解。代码只能证明当前实现，不能单独证明产品希望如此。
- **生成内容**：以生成器或配置源为准；生成物只在确有阅读价值时说明其来源。
- 旧材料中的“用户定”“用户要求”等归因仅是待核验的文字，不代表当前要求。无法从当前实现、直接证据或当前要求确认的内容，不写成确定事实；若影响实现或操作，将问题集中澄清，否则删除该断言。

遇到冲突时，先区分“现在实际上怎样”和“现在要求怎样”，不要把其中一方推断成另一方。当前要求不明确时保留明确的问题，不从旧决策叙述中补全答案。

## 只写当前需要的内容

- 活动文档描述现在有效的功能、操作步骤、接口约束和复现条件，使用当前时态与直接表述。
- 不记录已废弃方案、旧版本差异、历史争论、被推翻的猜测或“某日用户决定了什么”。版本控制记录变更历史；活动文档不承担编年史职责。
- 旧报告中的信息若仍影响当前使用，先重新核实，再提炼成当前结论和必要依据；不再需要的历史材料从活动文档中移除，不默认另建归档供 Agent 检索。
- 保留当前结论所需的最少验证信息，例如设备/固件条件、复现命令、预期结果或证据位置。仅当日期影响有效性时记录验证日期；不保留逐次决策时间线。
- 注释解释代码无法直接表达的非显然原因、约束、不变量或副作用。实现改变时同步更新或删除注释；不以“用户定”作为注释理由，不复述显而易见的代码。

## 按当前用途组织文档

- `AGENTS.md` 只保留 Agent 与开发者当前需要遵守的稳定规则、入口和必要指引，不复制领域细节。
- `README.md` 只承担当前项目介绍和可用的上手流程。
- `docs/README.md` 只索引当前仍在维护、读者实际需要的文档。
- 领域文档一个主题只保留一处当前说明；代码、配置或生成器已是唯一事实来源时链接过去，不另抄一份。
- 设备事实只在唯一权威来源维护，其他位置链接到该来源，不重复描述。
- 临时操作手册（如真机回归）若仍在使用，先按对应脚本核验后保留；流程已结束的，从当前操作入口移除。

## 文档与注释任务流程

1. **盘点范围**：扫描项目拥有的说明文件、代码注释/docstring、脚本帮助文字和配置说明；文件发现不能只依赖 Git 已跟踪列表。识别活动指南、临时操作材料、历史材料、第三方文件、生成物和原始日志。
2. **提取断言**：把会影响理解、开发或操作的事实拆成可核验的断言。日期、强语气、“实测”“唯一”“必须”和“用户定”等词只用于定位候选项，不作为真实性判据。
3. **独立核验**：代码行为查当前实现和检查；设备行为查直接探测及原始结果；产品意图查当前要求。不要用被审查文档、相互引用的文档或由同一未经验证前提生成的脚本彼此证明。
4. **裁定并处理**：确认的内容改写为当前结论；已过时或错误的内容修正或删除；无法确认的内容从规范性表述中移除，必要时列为待验证/待澄清事项。修正文档时一并检查它引用的脚本、命令和其他说明。
5. **收敛来源**：按上节的角色分工，每项易漂移的信息只保留一个权威来源。其他位置链接到该来源，或只保留读者完成当前任务必需的简短摘要。
6. **独立复核**：逐条对照当前依据审阅变更；检查文档链接、命令、路径、生成物说明和跨文档重复。审计台账与临时发现清理完成后移出项目活动文档，不把它们变成新的常驻知识库。

## 完成标准

- 任务范围内的活动文档和说明性注释均已盘点并作出保留、改写或删除处理。
- 当前事实与当前意图已分开；没有仅凭“用户定”、历史叙述或文档间相互引用而保留的规范性断言。
- 影响操作、用户数据或开发约束的断言均附可重查依据（实现位置、复现命令或当前要求来源）。
- 无法核实且会影响操作或实现的事项已明确列出；其他无依据的断言已移除。
- 操作说明与对应的当前脚本/配置一致；失效链接、路径和命令均已处理。
- 活动文档只留下当前仍有用途的知识，没有把历史叙述搬进新的归档或审计文档。

## 后续维护

实现、配置或当前要求变化时，只复核受影响的说明，并更新唯一权威来源及必要的引用。新增说明写当前行为和必要依据，不追加日期化的决策经过。编辑或核验文档、注释时，按本规范从第一步执行到完成标准。
