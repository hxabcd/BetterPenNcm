# 性能与动效优化

本文给出当前 BPN 的帧预算与动效问题清单，以及待实施的优化方案。
「现状」均可按代码位置核查；「建议」尚未实施，实施前按 §六 的探针验证。设备条件：S7 / 固件 4.23.0 / 1020×240 逻辑视口。

## 一、结论

BPN 体感「到处掉帧」由两个独立因素叠加：

1. **帧预算被占用**：隐藏的播放页/队列页每 500 ms 仍整页重渲染；播放页每次 tick 替换整份 state；进度条改 `width`/`left` 触发布局；切歌取色与下载会 fork 进程；启动链串行等待网络。
2. **状态变化没有过渡**：`src/` 内没有 `@keyframes`、没有 `animation:`、没有 `transition:` 声明（唯一相关的是 LyricPanel 的 `transitionDuration` 内联属性）。所有交互都是瞬时切换，一次迟到的帧就是一次可见的「跳」，也无法在重活期间维持视觉连续。

优先顺序：**P0 减少帧预算占用 → P1 增加短而轻的 transform/opacity 动效 → P2 用探针量化并决定是否引入原生扩展**。不要在 P0 之前大批量加动画，否则只是把卡顿做得更显眼。

## 三、P0：减少帧预算占用（未实施）

### 3.1 隐藏页停止订阅播放器

目标：只让当前可见页响应 500 ms tick。

做法：
- 页面在 `mounted` 订阅，在页面隐藏时 `player.off`，重新可见时 `this.st = player.state()` 再订阅。
- 先验证隐藏事件的派发：页面已实证 `this.$page.on('show', fn)` 可用；`hide` 是否同源派发需按 §六 探针确认。
- 若 `hide` 不可用，退而求其次：`show` 事件里标记「本页是栈顶」，非栈顶时订阅回调直接 return（不写 `this.st`）；或在每次 `navTo` 前由发起页显式 `off`。

验收：在当前页不动、后台播放时，隐藏页不再产生渲染；播放页在队列页打开期间不再响应 tick。

### 3.2 进度条改为 transform

目标：进度变化不触发布局。

```js
// 填充：固定 width:100%，只动缩放
fillStyle() {
  return {
    width: '100%',
    transform: 'scaleX(' + this.shownPct + ')',
    transformOrigin: '0 50%',
    backgroundColor: this.accent.c
  }
}
// 手柄：只动位移
knobStyle() {
  const g = seekGeometry()
  return { transform: 'translateX(' + Math.round(g.w * this.shownPct) + 'px)' }
}
```

注意：拖动 seek 时不要给这两个属性加 transition（跟手优先）；切歌时由数值直接归零。

### 3.3 日志构建期开关

- 生产构建关闭 `log()` 的 HTTP POST 与 `console.warn`，只保留错误级别。
- 热路径（播放 tick、封面入队/完成、下载轮询、滚动相关）按「状态变化」打点，不打每帧/每条。
- 现有 `logconfig.generated.js` 已承担构建期注入，可在同一生成物里加一个开关常量。

### 3.4 fork 治理

- 封面取色结果按「封面 id + url」落盘缓存（storage 或文件），跨会话复用；只对当前播放曲目/首页可见时执行；避免在列表滚动或页面转场期间启动。
- 下载保持「整文件优先」，分片只作兜底（现有策略正确）；批量下载可改为一个 detached 脚本顺序执行，JS 只轮询状态文件，减少每片 2 次 fork。
- 任何交互（点击、切歌、翻页）后 100 ms 内不启动新的 `process.exec`。

### 3.5 首屏

- 页面先渲染骨架与静态结构，`boot()` 里的网络校验（`fetchProfile`）不阻塞首屏；`loadHistory`/`loadLastState` 与页面并行。
- 每日推荐/歌单计数等数据按「先首屏可见、后次要」分批加载。

## 四、P1：动效（未实施，先按 §六 验证）

### 4.1 动效令牌

在 `src/utils/ui/tokens.js` 增加运动令牌（沿用现有 token 生成链）：

```js
MOTION = {
  fast: 100,    // 按压/图标切换
  base: 140,    // 浮层/页面内容进入
  slow: 200,    // 关闭/退出
  enter: 'cubic-bezier(0.2, 0.8, 0.2, 1)',
  exit:  'cubic-bezier(0.4, 0, 1, 1)',
  press: 'cubic-bezier(0.175, 0.885, 0.32, 1.275)'
}
```

规则：
- 只允许 `transform` / `opacity`（颜色过渡可用 `background-color`）；禁止 `width/height/top/left/margin` —— 后几个即使平台能插值（`left` 已观察到中间态），也会触发布局，动效仍不要用。
- 单个动画 ≤ 200 ms；同屏同时动画的元素 ≤ 3 个。
- 列表只动容器或首批可视行，**不要给 50 行逐行做过渡**。

### 4.2 动效清单

| 场景 | 建议 | 属性 | 时长/曲线 |
|---|---|---|---|
| 左栏键、行、卡片、播放键按下 | 立即回弹 | `scale(0.94)` + `opacity .85` | 100 ms / press |
| 播放/暂停/切歌 | 图标交叉淡入或轻弹 | `opacity` / `scale(1.06)` | 120 ms / enter |
| 多选态 | 勾选圈出现 + 遮罩淡入 | `scale(0.6)→1` / `opacity` | 120 ms / enter |
| 浮层、上下文菜单、弹窗 | 遮罩淡入 + 面板下移进入 | `opacity` / `translateY(10px)→0` | 140 ms / enter |
| 关闭浮层 | 反向过渡后再卸载（两段状态） | `opacity` / `translateY(0)→8px` | 120 ms / exit |
| 页面内容进入 | 整页只做一次淡入+微位移 | `opacity` / `translateX(6px)→0` | 140 ms / enter |
| 加载更多 | 只动容器（不做逐行 stagger） | `opacity` | 120 ms / enter |
| Loading | 旋转指示 | `rotate(0→360deg)` | 900 ms linear 循环 |
| 主题/背景切换 | 颜色过渡 | `background-color` | 160 ms / enter |

### 4.3 实现约束（平台）

- 只认单类名选择器：状态类用完整类名 + 内联 `:style`；动画类单独成类（如 `.is-press`）。
- 关闭动效需要元素在动画期间保持挂载：用 `open`/`closing` 两段状态 + 定时卸载，不要 `v-if` 立即删除。
- 含 slot 的组件内不要用 `v-if` 增删兄弟节点（见 [平台约束与自检.md](平台约束与自检.md)）；动效尽量加在普通节点上。
- 平台样式编译器接受 `animation` / `transition` 声明，但**只有写在 class（LESS）里的 `transition` 才插值，且仅限 `transform` / `background-color` / `opacity` / `left`；`font-size` / `color` 任何路径都不插值**（`@keyframes` 里写这两个属性还会让整条动画失效）。逐属性矩阵与探针页见 [平台约束与自检.md](平台约束与自检.md) 的「动画与帧调度」。
- 动画元素必须有固定几何，避免动画过程中文字换行/尺寸变化引起重排。

## 五、P2：测量

在 `src/pages/probe/` 增加 perf 探针（仅 `build_probe.sh` 构建，独立 appid）：

1. 帧间隔：`requestAnimationFrame` 连续采样 5 s，输出 P50/P95/max 与 >50 ms 的长帧数。
2. 阶段耗时：created / mounted / show / firstData / firstCover / bootDone。
3. 计数：`process.exec` 次数、`log()` 次数、页面 render 次数（`updated` 自增）、`<image>` 数量。
4. A/B 开关（config 或构建参数）：
   - 隐藏页停订阅 开/关
   - 进度条 transform / 原 width
   - 日志 POST 开/关
   - 封面取色 开/关
   - `lyricFull` 整首 / 窗口
   - 逐字歌词 开/关（`lyricWord`，逐字行每 33ms 推一次样式）
   - 歌词动画 开/关（`lyricAnim`，关 = 滚动/高亮/逐字全部瞬时）
   - 页面动效 开/关
   - 列表每批 50 / 30

每个开关只跑同一组场景，记录 P95；对比后再决定是否保留。

### 验收场景与目标

| 场景 | 观察 | 目标 |
|---|---|---|
| 首页静置（播放中） | rAF P95、隐藏页 render 次数 | 无隐藏页重渲染；P95 明显下降 |
| 列表滚动 / 加载更多 | 长帧数 | 无 >50 ms 长帧连续出现 |
| 播放页切歌、拖动 seek | 交互到首帧反馈、长帧 | 反馈 ≤1 帧；拖动无布局抖动 |
| 多选/排序/浮层开合 | 视觉连续性 | 有 100~140 ms 过渡且无掉帧 |
| 页面进入 | 首屏内容出现时间 | 骨架先行，数据后到不阻塞 |

## 六、待验证（先做这些再动代码）

1. `$page.on('hide')` 是否派发（`show` 已实证）；不可用时的替代可见性判断。
2. SFC/`<style>` 中的 `@keyframes` 是否编译生效；`animation-*` 与 `transition-*` 的时长单位（ms/s）。
3. `transform` 是否比 `width/left` 更省（同一元素两种实现对比 P95）。
4. `will-change` 是否被支持/有害（平台样式校验未列出，默认不用）。
5. 对 50 行容器加一次淡入是否引入额外布局成本。
6. 取色结果落盘缓存的颜色准确性与失效策略。
